# OpenClam · 研究原型

开盖使用外接显示器时，关闭内建显示器；全部外屏断开后恢复内屏。

提供常规关闭内屏和**驱动合盖实验模式**，不改变铰链传感器读数。**v0.4.0 增加一次最多 3 分钟的综合采样，在同一份报告中比较正常开盖、实验模式、真实合盖和重新开盖的显示状态。M3 实测至 v0.3.2，第二台外屏仍无信号，根因尚未确认；本版不能视为已解锁 M3 开盖双外屏。** 本版也移除恢复中多余的内屏关闭步骤，保留新增外屏重新启用实验。

要求 Apple Silicon MacBook 和 macOS 15 或更新版本。

**[下载研究预览版](https://github.com/try2love/OpenClam/releases)** · [安装与测试说明](docs/安装与测试.txt)

## 使用

下载 DMG，将 `OpenClam.app` 拖入“应用程序”后打开；自行构建可打开 `build/OpenClam.app`。在菜单栏找到 **OpenClam**：

- **关闭内屏，保留外屏**：保持外屏工作，内屏退出桌面并请求关闭面板。
- **恢复内建显示器**：结束当前会话并恢复内屏。
- **测试关闭 10 秒后恢复**：先试用一个短会话。
- **启用双外屏模式（实验）**：尝试关闭内屏并切换输出通道。请检查两台外屏都有正常画面后再点击保留；30 秒未确认会自动请求恢复内屏。系统列出两台显示器不代表它们已收到信号。
- **开始综合采样（3 分钟）**：后台约每 2 秒记录一次显示状态，同时记录配置通知、睡眠／唤醒事件和操作标记；采样本身不会切换显示状态。
- **结束采样并保存…**：提前结束综合采样并保存 JSON；达到 3 分钟后也可通过 **保存综合采样报告…** 导出。
- **导出实验报告…**：单独保存最近两次实验和当前显示状态，不会自动上传。综合采样报告也会附带经过筛选的实验记录。
- **退出并恢复内屏**：结束会话后退出。

只接受开盖、扩展显示模式且至少一台外屏正在显示的状态。启动应用不会自动关闭内屏。外屏重新接入后，也不会自行重新关闭内屏，需要再次点击。

每个关闭会话有独立守护进程。检测到全部外屏不可用、主程序退出、主程序心跳超过 12 秒未更新或短测到期时，守护进程请求恢复内屏。外屏状态每 0.5 秒检查一次；显示系统本身的更新和恢复还需额外时间。真正合盖时延迟恢复到重新开盖，避免与系统正常合盖行为冲突。

本地构建仅做 ad-hoc 签名，没有公证。无需安装驱动、root 权限、修改 SIP 或开机安全策略。

M3 开盖时只识别一台外屏也允许开始实验。接口不支持、通道无法确认或显示状态未稳定时会中止实验并请求恢复。若恢复后内屏仍异常，先结束采样并保存，再退出 OpenClam、合盖后重新开盖；不要重复启用实验模式。

## 一次综合采样

保持两台外屏线缆连接，采用扩展显示模式。从菜单选择 **开始综合采样（3 分钟）**，然后在同一次采样中完成：

1. 正常开盖，停留约 15 秒。
2. 启用双外屏实验模式。如果第二台无信号，停留约 10 秒后选择“无信号，恢复并记录”，将反馈写入同一份采样报告；若实验自动失败并恢复，直接继续。**不要为无信号画面选择保留。**
3. 等内屏恢复正常后，真正合上盖子约 15 秒，查看两台外屏是否都有正常画面。
4. 重新开盖，停留约 15 秒，再选择 **结束采样并保存…**。若采样已自动结束，选择 **保存综合采样报告…**。

时间不需要逐秒准确。采样本身只读，不会自动执行以上切换；请在保存前保持应用运行，**退出应用会终止采样**。自动结束后报告仍留在内存，需要手动保存；选择“重新开始综合采样（3 分钟）”会替换它，请先保存。关闭内屏会话仍在运行时保存按钮不可用，请先恢复内屏。报告汇总显示端点、framebuffer、电源和端口状态时间线，以及配置通知、睡眠／唤醒事件、操作标记和实验记录，不会自动上传。缺失或读取失败的字段记为 `unknown`，不能当作关闭或零值。报告不能替代物理画面观察，反馈时请同时说明各阶段第二台外屏是否有画面、恢复后内屏色彩是否正常。

## 当前验证范围

既有测试设备：M4 MacBook Air，macOS 15.6.1，两台原生外屏。下列实机结果按版本记录，不代表新版本已完成相同测试。

- 已实测：内屏退出桌面，两台外屏 ID 保持不变，定时恢复内屏。
- 已实测：强制结束关闭会话的主程序后，独立守护恢复内屏；8 项恢复判断测试通过。
- v0.2 的 M4 20 秒短测验证了显示列表和恢复，未验证 M3 新增输出。随后 M3 用户报告两台外屏中仅一台有信号，并报告恢复内屏偏紫；因此已撤回仅凭显示列表判定成功的做法。
- v0.3 为新增外屏选择其实际输出通道，恢复时重新识别内屏并恢复原模式；画面确认独立于显示器枚举。M3 的 v0.3.1 报告已确认选择请求发往正确通道并返回 0，驱动中已有外屏模式及新增端口活动，但第二台仍无画面；请求返回成功不足以证明输出正常。
- v0.3 已在 M4 验证：30 秒未确认自动恢复、切换中及预览中强杀主程序后恢复、辅助程序运行中强杀守护后清理残留进程并恢复。自动核对了内屏原模式；20 项恢复与预览判定测试通过。真实色彩仍需目视验收。
- 此前 v0.3 合盖后端已实测：切换过程中及启用后强杀主程序，守护均恢复内屏；切换中强杀会取消尚未提交的合盖请求。
- 面板关闭请求返回成功，但 IORegistry 的电源属性未提供足够的关电证据。背光是否实际熄灭需目视确认，不能据此宣称物理断电。
- 实际拔线恢复需要用户拔掉所有外屏完成硬件验收；恢复判断有自动测试。
- v0.3.1 已验证只读驱动模式／端口采样、生产应用报告导出、并发记录、两次会话保留及身份字段过滤；未新增显示切换请求。该版本未完成 M3 输出验收。
- v0.3.2 在 M4 两台外屏环境中通过了未确认自动恢复及主程序、守护异常退出恢复测试。但随后 M3 报告显示：移除额外面板关闭请求后，四个对应阶段的显示器和 framebuffer 状态均与 v0.3.1 相同，第二外屏仍无信号。恢复内屏时，四次尝试均在初次启用提交返回 0、随后读到内屏处于活动状态后，再次禁用内屏；之后重新启用返回 1001，最终内屏未恢复为活动状态。
- v0.4.0 删除上述额外内屏禁用循环，恢复时先启用内屏，再核对身份、唤醒状态和原模式。实验模式仅对新出现且通道已核对的外屏进行一次独立的禁用、启用配置，不直接重写模式或面板电源；M4 启用前已有的两台外屏跳过这一步。
- v0.4.0 在 M4 上通过了未确认预览自动恢复、切换中和预览中主程序异常退出恢复，以及守护进程在助手待执行时异常退出后的清理与恢复。另用独立恢复保护运行生产外屏助手，实测停用后重新启用同一外屏、原模式保持、另一台外屏不变、内屏原模式恢复。20 项恢复／预览判断、32 项外屏身份／切换判断和恢复不再禁用内屏的检查通过。这些测试未验证实际像素、色彩，也不能证明 M3 第二外屏已输出。
- v0.4.0 综合采样已在 M4 通过只读实测：8 秒内取得 4 份完整样本，覆盖 3 个显示端点、3 条显示通道和 6 个端口，采样前后显示配置一致；12 项扩展字段筛选及隐私检查通过。采样器的异步停止、子进程回收、超时、事件／样本／报告大小上限及延迟反馈保存测试通过。真实合盖期间的采样仍需 M3 实机完成。
- 不承诺改善温度或性能；尚无温度对照实验。
- 私有接口可能随系统更新变化。守护进程提供尽力恢复，不能在其自身也被终止、系统挂起或接口失效时保证恢复。

若恢复失败，先重新连接外屏或将盖子合上再打开。保留手工恢复入口：

```sh
build/OpenClam.app/Contents/MacOS/display-helper on --commit session
```

不要直接运行 helper 的 `off`：它绕过 OpenClam 的独立恢复守护。

## 构建与研究入口

```sh
bash scripts/build.sh
build/OpenClam.app/Contents/MacOS/OpenClam status
build/OpenClam.app/Contents/MacOS/OpenClam diagnostics
build/OpenClam.app/Contents/MacOS/OpenClam signal-capture 180
build/OpenClam.app/Contents/MacOS/OpenClam observe 60
build/OpenClam.app/Contents/MacOS/OpenClam trial 10
build/OpenClam.app/Contents/MacOS/OpenClam routing-trial 30
# 0 表示测试“30 秒未确认则自动恢复”，不是无限运行
build/OpenClam.app/Contents/MacOS/OpenClam routing-trial 0
build/OpenClam.app/Contents/MacOS/OpenClam self-test
```

`diagnostics` 将当前显示状态和最近实验记录输出为 JSON；“导出实验报告…”使用同一格式。综合采样报告另包含连续时间线。本地实验记录位于 `~/Library/Logs/OpenClam`，保留最近两次。报告不包含序列号、EDID、设备 UUID、恢复参数或屏幕内容。

`signal-capture 180` 进行 180 秒只读综合采样，结束后输出 JSON。

`status` 读取真实铰链报告、系统合盖状态与在线显示器，不收集设备序列号。`observe` 每秒输出一份 JSON，可用于比较真实开合盖前后状态。运行这些入口需要访问本机桌面会话；受限代理沙箱中可能无法读到显示器。

`probe-open` 仅在系统确认已开盖时发送同状态调试请求 `IOPMTestClamshellOpen`。它是权限探测，不是实现成功的判据；没有关闭事件、传感器写入、驱动安装或安全设置修改。

进一步的逆向发现与测试证据见 [研究记录](docs/RESEARCH.md)。

综合采样、驱动后端、M3 现场发现及验证边界见 [驱动合盖实现](docs/DIRECT-ROUTING.md)。

M3 的直接合盖路径预检、实测阻碍及采样步骤见 [M3 实验说明](docs/M3实验说明.md)。该研究工具独立于菜单栏应用，尚未实现双外屏解锁。
